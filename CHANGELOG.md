# История обновлений LUMQERA

Все заметные изменения собственного игрового ядра LumqeraCore. Формат версий `RC` означает **release candidate**, а не завершённый публичный релиз.

## 1.0.0-RC11 — надёжные клановые войны

- Принятие вызова на войну завершается только после подтверждённой записи в `wars.yml`. При ошибке возвращается прежний ожидающий вызов.
- Очки за PvP-победы сохраняются **до объявления** нового счёта; при отказе диска изменение очков и итоговых результатов откатывается.
- Завершение по таймеру и сдача клана сначала сохраняют результат; при ошибке записи активная война восстанавливается и не объявляется ложный победитель.
- Добавлено глубокое резервирование состояния клановых войн для безопасного отката изменённых счетов, статистики побед и вызовов.
- Усилена валидация длительности и цели войны при принятии вызова.
- Добавлены JUnit-тесты перезапуска, окончания по счёту и таймеру, ничьих, восстановления вызовов и отказов диска.
- Обновлены версии LumqeraCore, сайта, инструкции и Windows-сценарии сборки.

**Проверка:** GitHub Actions Windows/Linux на JDK 25 и Gradle 9.1.0. Настоящая игра на Paper с несколькими участниками остаётся отдельным этапом.

## 1.0.0-RC10 — безопасность территорий

- Загрузка `land.yml` теперь строго проверяет координаты чанков, UUID мира, структуру списка приватов и радиусы безопасных зон: повреждённые данные не превращаются в координаты `0,0`.
- Блокируются дубли названий безопасных зон, отличающиеся только регистром, а также повреждённые и неканонические идентификаторы миров.
- При ошибке сохранения приват территории откатывается в оперативной памяти. Удаление привата и изменение безопасной зоны также восстанавливают прежнее состояние, чтобы избежать расхождения с диском.
- Исправлено переполнение координат `int` в проверках соседних чанков.
- Добавлены JUnit-тесты проверки связности территории, границ координат, сохранности YAML и отката операций при ошибке записи.
- Обновлены Java-плагин, сайт, документация и скрипты сборки для RC10.

**Проверка:** GitHub Actions Windows/Linux, JDK 25 / Gradle 9.1.0, тесты и сборка JAR. Реальное тестирование на Paper остаётся обязательным.

## 1.0.0-RC9 — честный PvP и защита статистики

- Счётчики убийств и смертей больше не переполняются за пределами `Integer.MAX_VALUE`.
- Антифарм не сбрасывается из-за отката системного времени; отключённый антифарм не создаёт лишних записей.
- Отказ записи `pvp.yml` блокирует PvP-награды вместо ложного подтверждения победы; игрок получает уведомление, ошибка записывается в лог.
- При чтении `pvp.yml` отклоняются дублирующиеся UUID игроков, повреждённые счётчики и неверные временные метки.
- Добавлены регрессионные JUnit-тесты с реальной загрузкой YAML, антифармом, перезапуском и отказом записи.
- Обновлены версия и документация, скрипты Windows и GitHub Actions для RC9.

**Проверка:** автоматическая сборка Java 25 / Gradle 9.1.0 на Windows и Linux. Это не заменяет испытания на живом Paper.

## 1.0.0-RC8 — целостность кланов

- Строгая загрузка участников и офицеров из `clans.yml`: неправильный тип списка или элемента теперь вызывает ошибку вместо молчаливого удаления данных.
- Проверка дублированных офицеров, некорректного влияния клана и повторных UUID в сохранённых именах игроков.
- Приглашение от удалённого объекта клана теперь отклоняется; предотвращено переполнение времени окончания приглашения.
- Исправлено отображение версии в командах `/lumqera help` и `/lumqera status`.
- Добавлены автоматические тесты загрузки YAML, членства и приглашений.
- Обновлены метаданные плагина, сборочные скрипты, сайт и инструкции.

**Проверка:** GitHub Actions на Windows и Linux. Ручное тестирование на работающем Paper остаётся обязательным перед релизом.

## 1.0.0-RC7 — защита экономики и жалоб

- Проверки формата разделов `accounts`, `treasuries`, `reports` и `reviews`, чтобы повреждённые данные не выглядели пустыми.
- Регрессионные тесты загрузки экономических данных и обращений.
- Сборка с JDK 25 и Gradle 9.1.0.

Вспомогательные улучшения репозитория и сайта публикуются в истории [коммитов](https://github.com/Zeihos/LUMQERA/commits/main) и [pull request](https://github.com/Zeihos/LUMQERA/pulls?q=is%3Apr).
